# Sahaaya – Smart Healthcare Navigation System

**Your Health. Our Support.**

> **Proof-of-concept prototype.** Hospital information, waiting times, bed availability, token availability and Digital Twin values in this project are **simulated demo data**. Sahaaya is **not connected to any live hospital system**. It gives no medical advice. In an emergency call **112** (ambulance **108**).

Built for the Digital Twin Challenge (prototype and code submission).

![Home](docs/screenshots/home.png)

## 1. Problem Statement

When someone needs care, finding the right hospital and department is slow and stressful. People often do not know which nearby hospital offers a service, how crowded it is, how to book a visit, or what to do in an emergency. Language barriers make this harder.

## 2. Solution

Sahaaya is a single place to find a hospital or department, see a simulated picture of how busy it is, book an appointment with a token, get directions and reach emergency help. A local AI assistant answers simple questions in plain language, and the interface supports five languages.

## 3. Key Features

- 11 screens: Home, Login, Hospitals List, Hospital Details, Book Appointment, Voice & Language, Appointments & Tracking, Pharmacy & Labs, Token Allocation, Map View, Multi-Language.
- Hospital search by name, department, service or location, including simple sentences such as "Which hospital has cardiology?".
- Accounts: signup and login. Passwords are stored as salted scrypt hashes.
- Appointment booking with a demo token, saved in a SQLite database. Each account sees only its own appointments. Cancelling releases the token.
- Digital Twin card for each hospital (simulated, see below).
- Local AI assistant and "Explain with AI" (LM Studio), with graceful fallbacks when the AI is not running.
- Emergency button (`tel:112`) and an emergency safety reply.
- Voice search through the browser's speech recognition (Chrome or Edge).

![Appointments and tokens](docs/screenshots/booking-token.png)

## 4. Digital Twin Concept

A digital twin is a virtual copy of a real system that mirrors its state. In Sahaaya, each hospital has a twin that shows:

- estimated people waiting and estimated waiting time
- simulated bed availability
- simulated number of doctors on duty
- a simulated crowd level (Low, Moderate, High) and a 2-hour trend

**What is simulated and what is real:** the walk-in load, beds and doctors are generated by a smooth, repeatable model of the time of day (`backend/twin.js`). The only real input is the number of tokens booked **through Sahaaya**, which is read from the database and added to the queue. The numbers are never presented as live hospital data.

The twin lives in one file on purpose: a real deployment would replace its `simulate()` function with verified feeds, and the rest of the app would not need to change.

## 5. AI Assistant

- Runs on a local model through [LM Studio](https://lmstudio.ai) (OpenAI-compatible server). **No API keys are used**, and LM Studio is not exposed to the internet: only the backend talks to it, on `localhost`.
- The assistant is given the hospital data from the database plus the current twin values, and is told to answer only from that data, to give no diagnosis or medicine advice, and to keep answers short.
- "Explain with AI" turns a hospital's twin numbers into a short plain-language explanation.
- Every AI answer is labelled as AI-generated and carries a short note that AI can make mistakes.
- **If LM Studio is not available the app does not crash.** The assistant falls back to a simple keyword search of the database, and "Explain with AI" falls back to an automatic summary. Both say that local AI is unavailable in the current environment.
- Models tried in order: `gemma-3-1b-it`, `qwen3.5-0.8b`, `llama-3.2-1b-instruct`. Small models make mistakes and are weaker in Telugu, Tamil and Kannada.

![Assistant](docs/screenshots/assistant.png)

## 6. Healthcare Navigation

- Search and filter hospitals (Government or Private), view departments, doctors, services and sample timings.
- **Map / directions:** the buttons open Google Maps directions (Car, Bike or Walk) to the selected hospital from a demo start point. No Google API key is used. The map picture inside the app is a labelled demo and there is **no live GPS or live traffic**.
- Book an appointment: choose hospital, department, doctor, date and a fixed demo time slot, then receive a demo token.
- Pharmacy and lab service information (sample data, ordering is not connected).

## 7. Emergency Assistance

- The Emergency Help button is a `tel:112` link, so your phone opens its dialer. The app itself cannot place calls.
- If a message to the assistant mentions an emergency (for example chest pain or not breathing, in English, Hindi, Telugu, Tamil or Kannada), the app shows a fixed warning with a **Call 112** button. The AI model is **not** asked, and this also works when the AI is off.
- Sahaaya does not diagnose. It encourages people to seek professional emergency help immediately.

## 8. Multi-language Support

- The interface labels are available in English, Telugu, Hindi, Tamil and Kannada. The header and main labels change when you pick a language.
- Voice search uses the selected language's speech recognition when the browser supports it.
- The assistant is asked to reply in the selected language, but small models may answer in English instead.
- The translations cover main labels only and should be reviewed by native speakers.

## 9. Technology Stack

- **Frontend:** HTML, CSS, vanilla JavaScript, Tailwind CSS (CDN), Font Awesome
- **Backend:** Node.js 22.13 or newer, Express 4
- **Database:** SQLite through Node's built-in `node:sqlite`
- **AI:** LM Studio local server (optional)
- **Maps:** Google Maps direction links (no API key)

## 10. System Architecture

```
Browser (HTML + Tailwind + JavaScript)
      |  REST (JSON)
Express backend ---- SQLite (users, hospitals, appointments, tokens)
      |
      +---- Digital twin model (backend/twin.js)  [simulated]
      +---- LM Studio on localhost:1234  [optional, local only]
```

The backend also serves the frontend, so one command runs everything.

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/health` | Server and database check |
| POST | `/api/auth/register`, `/api/auth/login`, `/api/auth/logout` | Accounts |
| GET | `/api/hospitals?q=&type=` | List and search hospitals |
| GET | `/api/hospitals/:id`, `/api/search?q=` | Details and combined search |
| GET | `/api/care-services?kind=pharmacy\|lab` | Pharmacy and lab services |
| POST | `/api/appointments` | Book (login required), creates a token |
| GET | `/api/appointments`, `/api/tokens/:id` | My appointments and token status |
| POST | `/api/appointments/:id/cancel` | Cancel and release the token |
| GET | `/api/tokens/availability` | Simulated token capacity minus tokens booked through Sahaaya |
| GET | `/api/twin`, `/api/twin/:id` | Digital twin state and history (simulated) |
| GET | `/api/ai/status`, POST `/api/ai/chat`, POST `/api/ai/explain-twin` | Local AI |

## 11. Demo Data / Prototype Limitations

| Item | Status |
|---|---|
| Hospital names, doctors, addresses, timings | Sample data (Bhimavaram demo set) |
| Waiting time, queue length, crowd level | **Simulated** |
| Bed availability, doctors on duty | **Simulated** |
| Token availability | **Simulated** (demo capacity of 40 per department per day, minus tokens booked through Sahaaya) |
| Appointment time slots | Fixed demo slots |
| Tokens booked through Sahaaya | Real records in the local database, but **not** registered with any hospital |
| Accounts and appointments | Real records in the local SQLite database |
| AI explanations | Generated from the prototype data above, can be wrong |
| Hospital data source | **Not connected to any live hospital database** |

## 13. How to Run Locally

1. Install [Node.js](https://nodejs.org) (LTS, 22.13 or newer).
2. In a terminal inside the `backend` folder run:
   ```
   npm install
   npm start
   ```
   On Windows, if PowerShell blocks `npm`, use Command Prompt.
3. Open **http://localhost:3000**.
4. Sample demo account (local prototype only): `madhuri@sahaaya.care` / `demo1234`, or sign up with your own details.

The database file is created automatically in `backend/data/`.

**Optional AI:** install LM Studio, load a small chat model (for example Gemma 3 1B), open **Developer** and switch on **Start Server** (port 1234). Without it, the app still works and uses the fallbacks described above. To change the model or address, set `SAHAAYA_MODEL` or `LM_STUDIO_URL`, or edit `backend/config.js`.
